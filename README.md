# 🏠 Домашний Git-Сервер

Проект персонального Git-сервера с физическим контролем данных. Максимально оптимизирован: работает без графической оболочки (GUI), потребляя минимум ресурсов. Создавался под работу на Intel Atom 330 / 4GB RAM / Debian Server.

---

## 🚀 Быстрый старт (Скачивание и деплой)

Чтобы скачать скрипт развертывания `deploy.sh` и запустить его на сервере, выполните следующие команды в терминале сервера:

```bash
curl -sSLO https://raw.githubusercontent.com/AlexanderV823/personal-git-server/main/deploy.sh && chmod +x deploy.sh && ./deploy.sh
```

---

## 🛠 1. Работа в режиме чистого Git (Через консоль)

Если вы скачали сгенерированный сервером ключ и сохранили его как `home_git_key`, вы можете клонировать ваши репозитории по кастомному порту без ввода паролей.

*   **Создать новый репозиторий на сервере:**
    Зайдите на сервер по SSH и выполните:
    ```bash
    sudo -u git mkdir -p /home/git/projects/my-project.git
    sudo -u git git init --bare /home/git/projects/my-project.git
    ```

*   **Скачать пустой репозиторий на рабочий ПК:**
    *(Замените `SSH_ПОРТ` на порт, указанный вами при деплое, по умолчанию: 22)*
    ```bash
    git clone -c core.sshCommand="ssh -i ~/.ssh/home_git_key -p SSH_ПОРТ" ssh://git@IP_СЕРВЕРА/home/git/projects/my-project.git
    ```

*   **Связать уже существующий проект на ПК с сервером:**
    В папке с проектом на вашем ПК выполните:
    ```bash
    cd /путь/к/вашему/проекту
    git remote add origin ssh://git@IP_СЕРВЕ─A/home/git/projects/my-project.git
    git config core.sshCommand "ssh -i ~/.ssh/home_git_key -p SSH_ПОРТ"
    git push -u origin main
    ```

## 🔑 2. Привязка своих SSH-ключей (Если отказались от генерации)

Если при деплое вы выбрали ручную подготовку под существующие ключи, пробросьте свой публичный SSH-ключ со своего рабочего ПК на сервер одной командой:
*(Замените `SSH_ПОРТ` на реальное значение)*

```bash
ssh-copy-id -p SSH_ПОРТ git@IP_СЕРВЕРА
```

## 🌐 3. Если включена Веб-панель (Forgejo)

*   **🔗 Адрес в браузере:** `http://IP_СЕРВЕРА:ВЫБРАННЫЙ_ПОРТ` (Порт задается при установке, по умолчанию: 3000).
*   **📦 База данных при установке:** Обязательно выберите **SQLite3** (работает внутри одного файла, не нагружает процессор Atom 330 и не ест оперативной памяти).
*   **📂 Путь к репозиториям:** При первоначальной настройке в браузере укажите `/home/git/projects/`
*   **👑 Администратор:** Первый зарегистрировавшийся в веб-интерфейсе пользователь автоматически получает права администратора.

## 💾 4. Бэкапы и Дублирование в GitHub

### 🗄 Резервная копия базы данных SQLite3
Если вы включили бэкап при деплое, сервер автоматически делает горячий слепок базы данных (пользователи, доступы, настройки) без остановки сервера.
*   **Время старта:** Выбирается индивидуально пользователем при установке скрипта.
*   **Срок хранения:** Выбирается пользователем при деплое (старые файлы автоматически удаляются).
*   Папка с бэкапами на сервере: `/var/backups/forgejo/`

### 🔄 Автоматическое дублирование (Mirroring) репозиториев на GitHub
Чтобы при каждом вашем `git push` на домашний сервер код автоматически отправлялся резервной копией на GitHub:
1. Создайте пустой репозиторий на GitHub.
2. В веб-панели вашего домашнего Forgejo зайдите в настройки нужного репозитория: **Настройки -> Репозитории хранения -> Настройки зеркалирования**.
3. Введите адрес вашего репозитория на GitHub и укажите ваши учетные данные (Personal Access Token от GitHub).
4. Включите галочку **«Автоматически обновлять это зеркало при push»**.

## 🔒 5. Безопасность и зоны доступности (UFW)

Скрипт автоматически настраивает брандмауэр `ufw` под ваши задачи. В процессе установки вы можете индивидуально выбрать зону доступности для каждого из портов:
*   **Локальный режим:** Доступ открывается **строго для вашей домашней подсети** (автоматически определяется подсеть роутера, например `192.168.1.0/24`).
*   **Глобальный режим:** Порт открывается для всего внешнего мира (для проброса портов через Keenetic наружу).

*   **Проверить статус и активные правила файрвола на сервере:**
    ```bash
    sudo ufw status verbose
    ```

## 🔍 6. Проверка доступности и диагностика сервера

Выполните эти команды **на самом сервере по SSH**, чтобы убедиться, что всё работает корректно (замените `ВЫБРАННЫЙ_ПОРТ` на порт веб-панели):

*   **Проверить статус службы веб-панели:**
    ```bash
    sudo systemctl status forgejo
    ```
    *(Должно быть написано `active (running)` зеленого цвета).*

*   **Проверить, слушает ли сервер порт веб-панели:**
    ```bash
    sudo ss -tulpn | grep :ВЫБРАННЫЙ_ПОРТ
    ```

*   **Проверить доступность веб-интерфейса локальным запросом:**
    ```bash
    curl -I http://localhost:ВЫБРАННЫЙ_ПОРТ
    ```
    *(Должен вернуться ответ `HTTP/1.1 200 OK` или перенаправление `302`).*

*   **Проверить статус планировщика бэкапов (Cron):**
    ```bash
    sudo -u git crontab -l
    ```
    *(Вы увидите строку с вашим временем и путем к скрипту бэкапа).*

## 👥 7. Консольное администрирование пользователей (CLI Forgejo)

Все команды выполняются **на сервере по SSH** от имени пользователя `git`.

*   **🔑 Сброс или изменение пароля любого пользователя:**
    ```bash
    sudo -u git forgejo admin user change-password --username ИМЯ_ПОЛЬЗОВАТЕЛЯ --password НОВЫЙ_ПАРОЛЬ
    ```

*   **➕ Создание нового пользователя через консоль:**
    ```bash
    sudo -u git forgejo admin user create --username ИМЯ_ПОЛЬЗОВАТЕЛЯ --password ПАРОЛЬ --email email@example.com
    ```

*   **👑 Назначение пользователя Администратором:**
    ```bash
    sudo -u git forgejo admin user toggle-admin --username ИМЯ_ПОЛЬЗОВАТЕЛЯ
    ```

*   **🚫 Блокировка (деактивация) пользователя:**
    ```bash
    sudo -u git forgejo admin user delete --username ИМЯ_ПОЛЬЗОВАТЕЛЯ
    ```
    *(Эта команда не удаляет репозитории пользователя сразу, а безопасно деактивирует аккаунт, предотвращая вход).*

*   **📋 Вывести список всех зарегистрированных пользователей:**
    ```bash
    sudo -u git forgejo admin user list
    ```

## 🚨 8. Полное или выборочное удаление сервера (Очистка)

### 🤖 Способ А. Автоматическая очистка через скрипт
Если вам необходимо **полностью удалить** все компоненты, запустите ваш скрипт деплоя повторно:
```bash
./deploy.sh
```
И выберите пункт меню **`2) ПОЛНОЕ УДАЛЕНИЕ всех компонентов (очистка)`**. Скрипт сам найдет и точечно сотрет все правила в UFW по номерам строк (сохранив ваш доступ по SSH), запросит текстовое подтверждение `yes` и полностью очистит систему автоматически.

### 🛠 Способ Б. Ручная выборочная очистка (Пошагово)
Если вам нужно удалить только отдельные части сервера вручную, используйте соответствующие команды ниже:

*   **🗑 Удаление только веб-панели Forgejo (Код репозиториев останется):**
    ```bash
    # Останавливаем и удаляем службу автозапуска
    sudo systemctl stop forgejo || true
    sudo systemctl disable forgejo || true
    sudo rm -f /etc/systemd/system/forgejo.service
    sudo systemctl daemon-reload

    # Удаляем бинарный файл, конфигурацию и логи панели
    sudo rm -f /usr/local/bin/forgejo
    sudo rm -rf /var/lib/forgejo
    sudo rm -rf /etc/forgejo
    ```

*   **⚠️ Безвозвратное удаление ВСЕХ репозиториев и пользователя git:**
    ```bash
    # Удаляет пользователя и полностью стирает его домашнюю папку /home/git со всеми проектами
    sudo deluser --remove-home git || true
    sudo rm -rf /home/git
    ```

*   **📂 Удаление только резервных копий и скрипта бэкапа:**
    ```bash
    # Стирает папку со слепками SQLite3 и сам исполняемый файл бэкапа
    sudo rm -rf /var/backups/forgejo
    sudo rm -f /usr/local/bin/forgejo-backup.sh
    
    # Очистка задачи в cron (откроется редактор, удалите строку со скриптом бэкапа)
    sudo -u git crontab -e
    ```

*   **🧹 Ручное удаление правил портов из брандмауэра UFW:**
    ```bash
    # 1. Смотрим список правил с номерами строк
    sudo ufw status numbered
    
    # 2. Удаляем нужное правило по его номеру (например, №3)
    sudo ufw delete 3
    
    # 3. Перезагружаем файрвол для применения изменений
    sudo ufw reload
    ```
